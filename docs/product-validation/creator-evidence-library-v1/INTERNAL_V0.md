# 内部产品 V0 合同

状态：`in_progress / no_external_recruitment`

## 目标

用用户自己的 50—100 条真实收藏，完整交付一次：

> 真实收藏 → 本地可追溯证据库 → 3 个账号匹配选题证据包 → 1 个可继续创作的内容大纲

内部 V0 证明的是方案已经可打开、可演示、可重复交付，不证明市场需求成立。

## 私有输入与输出边界

- 真实收藏、原始转录、媒体、账号信息和运行状态只能进入 Git 忽略的本地目录；
- 公开仓库只保存合同、验证器、脱敏结构和经人工确认的演示；
- 不读取、打印或保存密码、Cookie、Token、二维码内容和浏览器 storage；
- 不自动修改收藏、发布内容或联系第三方。

## V0 交付物

1. `INPUT_MANIFEST.json`：输入、去重、成功、不可用和来源类型对账；
2. `library/`：可搜索的本地 Markdown 证据库；
3. `TOPIC_PACKS.md`：3 个账号匹配选题，每个绑定至少 2 条真实来源；
4. `CONTENT_OUTLINE.md`：从 3 个选题中选择 1 个形成证据型内容大纲；
5. `DELIVERY_RECEIPT.json`：运行时间、人工步骤、失败、隐私检查和文件哈希；
6. `DEMO/`：用户批准后才能生成的脱敏演示材料。

## 验收门槛

- 处理 50—100 条真实收藏；
- 输入总数等于成功、重复和不可用数量之和；
- 任取有效素材能够回到原链接、作者和关键出处；
- 来源观点、用户判断和 AI 推断使用不同字段；
- 每个选题至少引用 2 条真实来源，不使用泛化热词冒充证据；
- 用户能独立打开资料库、搜索并回到来源；
- 第二次运行不重新手工搭建目录和合同；
- 标准交付工时能够压到 3 小时以内；
- 私有输入不进入 Git，脱敏演示不含账号和私人收藏信息；
- 用户明确批准内部 V0 结果后，外部招募门才允许打开。

## 禁止扩张

内部 V0 不新增 SaaS、手机 App、多租户、付费系统、移动同步、团队权限、自动写完整脚本或新平台支持。缺少某项能力时先用有界人工步骤完成并记录工时，等待付费用户重复验证后再产品化。
