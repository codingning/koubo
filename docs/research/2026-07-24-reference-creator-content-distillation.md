## 2. 视频一：《在场即信任》

### 2.1 博主的核心论证

```text
技术和 AI 降低创造成本
→ 人人都能生产内容或产品
→ 供给增加，但注意力与用户没有同步增加
→ 分发成为更稀缺的能力
→ 新技术早期的信息差只能提供短期红利
→ 知识、文案、方法和薄功能都会被复制或吸收
→ 普通人应把短期红利转化为信任
→ 通过长期、真实、可核验的在场历史积累信任
```

### 2.2 值得保留的观点候选

1. **能生产不等于有人看、有人用。**
   - 证据时间码：`01:46–02:19`
   - 可迁移含义：选题不能只讨论“做出了什么”，还要说明它解决谁的什么问题，以及观众为什么会在意。

2. **工具越普及，纯信息与纯复制越难形成长期差异。**
   - 证据时间码：`02:20–03:25`、`05:17–05:55`
   - 可迁移含义：一篇任何 AI 都能写出的通用稿，不足以支撑个人账号；需要真实经历、判断、取舍与证据。

3. **信息差是入场窗口，不是长期壁垒。**
   - 证据时间码：`04:01–04:49`
   - 可迁移含义：热点内容必须留下热点消失后仍有价值的方法、记录或作品，不能只放大焦虑。

4. **长期信任来自一段可回看的行动历史。**
   - 证据时间码：`08:18–09:04`
   - 画面字幕核对：核心词为“在场”“Build in Public”。
   - 可迁移含义：用户的真实项目、第一版、失败、返修和结果可以形成连续证据，而不是被包装成孤立的成功故事。

5. **AI更适合放大真实行动，不适合替代个人判断与经历。**
   - 来源：对全片论证的抽象，不是博主逐字原句。
   - 可迁移含义：AI生成的表达必须落回用户真实做过的事，不能让模型制造“看似有深度”的身份。

### 2.3 不应直接吸收的部分

- “普通人一定要做自媒体、一定要做 AI”是未经限定的普遍命令。
- “可复制就不值钱”过于绝对；稳定交付、服务、规模、数据与低成本同样可以形成价值。
- “普通人拿不到分发权”忽略搜索、社群、邮件、客户关系和口碑等部分自有分发。
- “信息差＋复制”被描述为快速挣钱方法，容易滑向焦虑营销，与账号真实性边界冲突。
- “信任无法被复制或吸收”只能理解为相对更难复制；信任仍会因失约、错误、平台变化而损耗。
- 持续出现只能增加熟悉感；没有持续价值、诚实与兑现，不能自动生成信任。
- Build in Public 需要隐私、雇主知识产权、客户信息和未公开项目边界。

## 3. 视频二：《一条视频顶一百条的拍法》

### 3.1 博主的核心论证

```text
大量重复不等于学习
→ 先拍一条尽量简单的基线视频
→ 发布前记录对结果、优点和缺点的预估
→ 约定时间后读取真实后台数据
→ 让 AI 辅助提出问题原因与改进假设
→ 每次只验证一个主要改动
→ 再发布、再观察、保留或淘汰方案
→ 把问题、假设、修改和结果记入“错题本”
→ 长期形成个人化的方法资产
```

### 3.2 值得保留的观点候选

1. **学习目标是修正错误，不是用数量感动自己。**
   - 证据时间码：`00:33–01:12`、`08:42–08:59`
   - 可迁移含义：每条视频需要一个清楚的学习问题，不能把“又发了一条”当作进步证明。

2. **先做低变量基线，才能更容易定位问题。**
   - 证据时间码：`01:40–02:15`
   - 可迁移含义：第一次验证应减少非必要变量，先确认内容、表达和证据是否成立。

3. **发布前先写下预估，避免看完数据再编故事。**
   - 证据时间码：`02:15–02:50`
   - 可迁移含义：记录“我预计哪里好、哪里差、为什么”，再和结果对照。

4. **AI是诊断假设生成器，不是裁判。**
   - 证据时间码：`03:30–05:14`
   - 博主明确说 AI 的改进方案“不一定对”。
   - 可迁移含义：AI应输出多个原因与验证办法，并标注不确定性，不能把一次模型判断写成事实。

5. **一次只验证一个主要改动。**
   - 证据时间码：`05:14–06:04`
   - 可迁移含义：如果标题、内容、剪辑、发布时间一起变，Agent不得把结果归因于其中一个变量。

6. **失败方案也要进入版本记录。**
   - 证据时间码：`06:04–07:08`、`07:50–08:40`
   - 可迁移含义：保存问题、假设、版本、结果和淘汰理由，才能避免重复试错。

7. **实验过程本身可以成为观众有用的内容。**
   - 证据时间码：`07:50–08:40`
   - 可迁移含义：真正值得讲的不是“我用了 AI”，而是“我原来怎么判断、哪里错、改了什么、结果怎样”。

### 3.3 不应直接吸收的部分

- 视频没有展示真实后台、AI诊断、修改前后对照，因此只证明博主提出了方法，不证明方法在该案例中有效。
- “一条顶一百条”是修辞，不是数量关系。
- 24 小时不一定是稳定观察窗口；新账号、低播放量和长尾分发的噪声可能很大。
- 不同视频的题材、受众、发布时间与流量环境都在变化，单变量设计也不能自动证明因果。
- “短视频只有十几个、二十几个问题”“照做一定进步”属于未经本片证明的经验泛化。
- 从错题本到写书、课程、专栏和赚钱，还缺受众需求与真实转化验证。
- 给 AI 视频链接前需确认模型能否读取；更稳妥的输入是转录、画面说明、指标、目标和隐私处理后的证据。

## 4. 视频三：《做一件事就把它做成资产》

### 4.1 博主的核心论证

```text
一次性完成任务后丢弃成果
→ 下次仍从零开始
→ 先把一个重复问题做成粗糙的 1.0
→ 放进真实使用中暴露错误
→ 自动化失效时暂停，并退回人工把过程走通
→ 把验证后的解决过程重新编码进系统
→ 持续形成 2.0、3.0 等版本
→ 人从重复执行转向监控、维护与处理例外
→ 复用系统、知识和问题库，降低未来成本并产生新内容
```

### 4.2 值得保留的观点候选

1. **判断资产的简单问题：明天从 0 开始，还是从已有版本开始？**
   - 证据时间码：`00:00–00:23`、`04:53–06:06`
   - 可迁移含义：项目分享必须指出留下了什么可复用成果，而不是只报告“做完了”。

2. **第一版可以很粗糙，但必须解决一个真实、重复的小问题。**
   - 证据时间码：`00:49–01:42`
   - 可迁移含义：资产可以是清单、模板、FAQ、案例库、Skill、流程或最小自动化，不必一开始就是完整产品。

3. **真实使用暴露的问题才决定下一版。**
   - 证据时间码：`01:42–01:59`
   - 可迁移含义：不要凭空规划十个功能；先展示一次使用、一次失败和一个具体缺口。

4. **自动化失效时，先退回人工把正确过程走通。**
   - 证据时间码：`01:59–02:47`、`02:48–03:22`
   - 可迁移含义：AI Agent遇到新问题时应暂停、澄清真实意图、人工处理并记录，而不是继续自信输出。

5. **复利来自小版本的持续叠加，不是第一次搭建。**
   - 证据时间码：`03:25–04:24`
   - 可迁移含义：内容可以展示版本之间具体多了什么、修复了什么、仍有什么边界。

6. **成熟系统不会消灭工作，只会把工作从重复执行转为维护例外。**
   - 证据时间码：`03:49–04:24`、`05:44–06:06`
   - 可迁移含义：不得把“自动化”说成完全无人值守；必须说明监控、人工确认、维护与回滚。

7. **知识资产可以同时服务交付、选题和用户研究。**
   - 证据时间码：`04:28–04:52`
   - 可迁移含义：真实用户问题可以进入问题库，也能形成后续内容，但必须保护隐私并验证代表性。

### 4.3 不应直接吸收的部分

- “穷人和富人的区别”是未经论证的价值标签，不能作为 Agent 的说服方式。
- “一百多个版本”“八千多条问题”“已经赚钱”是博主自述，画面没有独立证据。
- 不是所有任务都值得资产化；低频、一次性、快速过时或维护成本过高的任务可能不值得系统化。
- “先粗糙上线”只适用于低风险、可撤回、可监控、有人工兜底的场景。
- 文档和自动化只有被真实复用并产生结果时才是资产，否则可能只是库存。
- 旧答案可能过时或缺乏上下文；医疗、法律、财务、隐私等高风险问题不能直接复用。
- “覆盖旧版本”不应被照搬；Koubo需要保留版本、证据和回滚能力。

## 5. 跨三条视频的可迁移模型

以下是 Codex 对三条视频的综合抽象，不是博主的原始命名。

### 5.1 三类可积累资产

| 资产类型 | 核心问题 | 对用户账号的意义 |
| --- | --- | --- |
| 信任资产 | 观众为什么相信这是你真实做过的？ | 公开连续的行动、失败、返修、结果和边界 |
| 学习资产 | 这次试验让下一次少犯了什么错？ | 保存问题、假设、改动、数据、结果和淘汰理由 |
| 系统资产 | 下一次能否从已有版本继续，而非重来？ | 沉淀模板、Skill、流程、案例库、检查表或自动化 |

一条内容不必同时拥有三类资产，但 Content Strategist 必须判断它主要积累哪一种，以及观众能从中获得什么。

### 5.2 适合 Koubo 的统一内容逻辑

```text
用户先提出真实方向
→ 找到具体受众与真实问题
→ 确认用户已有经历、证据和独特判断
→ 识别一个可验证的问题或冲突
→ 展示行动、第一版、失败或限制
→ 说明一次具体调整与结果
→ 提炼观众可复用的方法或最小行动
→ 记录本次形成的信任、学习或系统资产
```

### 5.3 “通用 AI 稿”淘汰测试

如果把创作者姓名、项目名和工具名删除后，任何 AI 账号都能原样发布，说明方向仍然过于通用。至少补足一项：

- 真实行动；
- 原始证据；
- 失败或反例；
- 具体取舍；
- 版本变化；
- 用户自己的判断；
- 可由观众当天执行的动作。

## 6. Content Strategist 候选工作规则

### 6.1 权限边界

- 必须由用户先提供方向，除非用户明确要求帮助寻找选题。
- 先访谈和分析，不直接生成口播稿。
- 无权自行换题；只能建议拆分、缩小、补证、延后或拒绝。
- 用户确认分析与方向后，Script Agent 才能开始成稿。
- 博主观点只作为候选分析镜头，不是必须套用的模板。

### 6.2 每次方向分析的八个问题

1. **受众**：处于什么具体状态的人会关心？
2. **收益**：看完后，他能理解、判断或完成什么？
3. **真实性**：用户真实做过什么，原始证据在哪里？
4. **非通用性**：为什么这不是任何 AI 都能写出的泛泛内容？
5. **实验性**：本次要验证什么问题、假设或取舍？
6. **资产性**：它主要沉淀信任、学习还是系统资产？
7. **可复制性**：普通观众能拿走哪个步骤、清单、判断或最小动作？
8. **风险**：是否存在过度因果、隐私、版权、雇主归属、金额、数据或未来结果声明？

### 6.3 输出合同

Content Strategist 应只输出：

1. 对用户真实想法的复述；
2. 最可能的受众与观众收益；
3. 方向的优点；
4. 方向的弱点、普通观众可能不关心的原因；
5. 已有证据与缺失证据；
6. 可验证的核心问题；
7. 单篇、系列或暂缓的建议；
8. 最多三个下一轮高价值问题；
9. 状态：`可进入成稿 / 补证后再写 / 方向需重构 / 建议放弃`。

在用户确认前，不输出完整口播稿、标题合集或剪辑方案。

## 7. Ordinary Viewer Critic 候选规则

### 7.1 代表的观众

- 每天看到很多 AI 内容、收藏很多方法，但还没有真正开始行动；
- 不是程序员，不默认理解 Agent、Skill、工作流、API 等术语；
- 时间有限，对创作者的项目本身没有天然兴趣；
- 会问“这和我有什么关系”“我为什么信你”“我今天能做什么”；
- 对空泛成长故事、项目汇报、AI万能论和未经证明的结果高度敏感。

### 7.2 评审阶段

1. **稿件评审**：读取已批准方向与口播稿，不读取 Script Agent 的自我解释。
2. **成片评审**：读取匿名成片、转录和必要事实表，不读取作者、Agent名称和导演理由。

现有 Blind Critic 与 Retention Critic 可继续负责匿名质量和留存；Ordinary Viewer Critic 专注观众价值、可信度、理解成本和行动欲望，避免职责重复。

### 7.3 强制检查项

- 前几秒是否说清“这和我有什么关系”；
- 是否把个人项目当成观众必须关心的主角；
- 是否能被任意 AI 账号无差别复述；
- 关键结论是否有真实行动或证据；
- 是否把相关性、单次结果或 AI 猜测说成因果；
- 是否解释了专业词，还是在用术语制造高级感；
- 是否给出一个普通人今天能完成的动作；
- 所谓“资产、系统、Agent、有效、自动化”是否具体可见；
- 是否只展示成功，隐藏失败、限制和人工工作；
- 是否为了激励而使用羞辱、焦虑或穷富标签；
- 观众是否有真实的收藏、分享或评论理由；
- 即使观众不关注下一集，这一条是否仍然给了完整价值。

### 7.4 输出合同

Critic 必须直接输出：

1. **一句最尖锐结论**：为什么我会划走、不信或不收藏；
2. **最多三个阻断问题**：引用稿件句子或成片时间码；
3. **观众价值缺口**；
4. **可信度与证据缺口**；
5. **最小可执行修复**，不擅自换题或整篇重写；
6. **观众决定**：`继续看 / 可能收藏 / 只会划走 / 整体不接受`；
7. 对主观偏好、事实错误和不确定判断分别标注。

Critic 可以尖锐，但不能侮辱创作者，也不能用情绪代替理由。允许结论为“整体不接受”，不强行选一个相对较好的版本。

## 8. 不进入 Agent 的黑名单规则

- 不把“普通人一定要……”写成默认开头。
- 不用“穷人和富人的区别”制造羞耻或焦虑。
- 不鼓励靠复制原作者表达、案例或人设获取短期收益。
- 不把一次数据变化写成某个修改的确定因果。
- 不把 AI 建议写成平台真相。
- 不把持续发内容等同于获得信任。
- 不把完成文档或自动化等同于形成资产；必须有真实复用。
- 不声称自动化完全无人值守。
- 不使用未核验的收入、版本数、问题库规模和成功率。
- 不因博主说法有启发性，就删除其适用条件、反例和伦理边界。

## 9. 当前结论与运行门禁

三条视频最值得吸收的不是某个固定脚本公式，而是三种判断方式：

1. **在场判断**：这条内容有没有增加一段真实、可核验的行动历史？
2. **学习判断**：它有没有记录一个问题、假设、修改和结果？
3. **资产判断**：下一次能不能从已有版本继续，而不是重新从零开始？

用户于 2026-07-24 明确要求 Content Strategist 参考这些观点分析其每次提出的方向，并要求 Ordinary Viewer Critic 在稿件和成片后给出尖锐点评。因此本知识包可以进入受限顾问层，但仍须满足：

- 不修改现有品牌骨架；
- Content Strategist 在用户确认前不创建完整稿件；
- 不把博主自述当成已验证事实；
- 不自动晋升长期记忆。

当前实现把它们作为可替换的 advisory knowledge 使用；任何单条原则仍可由用户拒绝、修改或废弃，不影响用户拥有选题、成稿确认、生产批准和发布权。

## 10. 角色级开源复用评估
