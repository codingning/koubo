## 2. M1：Remotion 是镜头级动效工具，不是自动替代全部剪辑

### 作者观点与画面证据

1. **先讨论方案，再逐镜头实现、自检、预览和本地渲染。**
   - 时间码：`01:46–02:13`。
   - 作者先要求 AI 说明方案，确认后再执行；每完成一个镜头进行检查，随后打开预览并渲染到本地。
   - 画面证据：定向联系表在 `01:52` 显示方案交互，在后续画面显示预览和本地项目过程。

2. **UI、软件演示和数据图表是作者认为的优势区，但最终质量依赖外部组件。**
   - 时间码：`02:14–03:18`。
   - 作者认为 UI、终端、打字机、界面运动和数据可视化适合 Remotion；同时明确指出图表观感的关键还包括所选前端图表库。
   - 画面证据：联系表显示数据流向图、终端界面、图表和真人讲解交替出现。

3. **地图不能依靠模型臆造，必须接真实底图或数据源。**
   - 时间码：`03:20–03:51`。
   - 作者把同提示词的失败结果与真实地图底图/API 路径进行对比，强调模型脑补不足以支撑严肃地图动画。
   - 可迁移含义：凡是声称位置、路线、比例或统计关系的画面，都应绑定真实数据，而不是用“看起来像”的动效冒充证据。

4. **难以口述的 3D 参数应暴露为可调属性。**
   - 时间码：`04:37–04:49`。
   - 作者建议把远近、大小、角度等参数暴露出来，在预览界面直接调整，而不是反复用自然语言猜数值。
   - 可迁移含义：审美分叉若能被参数化，应转成可寻址属性和有限预览，不应增加提示词轮次掩盖不确定性。

5. **短动效片段与实拍组合，比强行用一个引擎做完整视频更合适。**
   - 时间码：`04:50–05:08`、`05:51–06:28`。
   - 作者展示透明序列与剪辑软件合成，并说明自己通常让 Remotion 生成一个个辅助讲解的短片段；长视频则按分镜、时间线骨架、逐镜头制作、整体节奏/风格/转场调优推进。
   - 作者还建议把分辨率、帧率、动画偏好等写入项目说明，以减少重复沟通。

6. **作者自己的能力表不是官方产品结论。**
   - 时间码：`06:31–06:49`。
   - 作者主观划分为：UI/软件、代码/终端、数据图表更擅长；2D/3D 需要外部库；粒子/流体、实拍合成不建议硬做；完整剪辑仍交给传统剪辑软件。
   - 该划分只代表其工作流经验，不能被写成 Remotion 的官方适用性排序。

### 反例与禁止扩大

- 标题中的“告别 AE”“超过 99%”属于宣传表达，视频没有提供覆盖所有任务、成本和质量的独立对照实验。
- 公开评论中有人明确反映素材准备、细节描述和总体效率问题，说明“能做”不等于“低成本做得好”；评论只作为风险信号，不作为普遍结论。
- 作者展示的图表库、地图服务、3D 资产和第三方工具各有自己的许可证、密钥、费用、数据准确性和退出成本，不能随教程整体继承。
- 不复制作者的提示词、项目说明、案例、画面设计、3D 资产、透明序列或能力表视觉样式。

## 3. M2：先把字幕变成语义时间轴，再决定画面结构

### 作者观点与画面证据

1. **“根据字幕生成视频”不是充分需求。**
   - 时间码：`01:07–01:22`。
   - 作者列出直接生成常见失败：画面重复、与口播不同步、信息拥挤、特效廉价。
   - 画面证据：联系表以“直接让 AI 生成大概率会翻车”和问题清单明确呈现失败条件。

2. **以 SRT 时间码作为画面时间轴，禁止提前剧透后文。**
   - 时间码：`01:35–02:06`。
   - 当前口播到哪一句，只出现该句对应的标题、卡片或关键词；后一个信息点在对应语音开始后再出现。
   - 可迁移含义：视觉进度应由实际语音时间驱动，而不是按脚本字数平均分配，也不能为了画面热闹提前展示结论。

3. **根据语义密度选择版式。**
   - 时间码：`02:08–02:24`。
   - 单一重点适合大标题、关键词或中心卡；步骤适合列表、流程图或步骤卡；信息过多时拆成多个场景。
   - 这是“语义角色到画面结构”的候选路由，不是固定模板清单。

4. **禁止无目的效果堆叠，并统一全片视觉语言。**
   - 时间码：`02:24–03:17`。
   - 作者反对玻璃拟态、颗粒纹路、噪点、光斑、闪白、故障等无目的叠加；同时要求统一配色、字幕和线条。
   - 生成后先预览文字重叠、字幕遮挡、画面过空和节奏过急，再进入最终渲染。

5. **关键分叉必须由人确认。**
   - 时间码：`03:18–04:08`。
   - 主题与比例、网页预览、哪些经验能否升级为规则，都由人确认；作者将其概括为“AI 执行，人工判断”。
   - 可迁移含义：生成、预览、规则晋升是三种不同权限，不能用一次“确认”同时授权。

6. **不同内容应选择不同视觉功能。**
   - 时间码：`04:18–05:47`。
   - 观点口播：把字幕抽象成标题、关键词、卡片和总结页；
   - 工具讲解：使用输入卡、流程箭头、功能标签和结果页；
   - 真实录屏：录屏作证据，卡片、箭头和标签负责解释；
   - 真人口播：真人是主画面，图形避开脸部和字幕区；
   - 清单资料：优先列表、表格、卡片和对比面板，保持稳定可读。

7. **主题可以变化，稳定规则不能丢。**
   - 时间码：`05:48–06:12`。
   - 作者展示多套背景和主题，但把同步、清楚、统一、不抢内容列为跨主题稳定约束。

### 反例与禁止扩大

- 本条视频同时是作者自有 Skill 的展示和推广，没有公开完整实现、测试集、失败样本或可独立审计的复刻结果。
- “内置八种风格”“补了二十二套主题”只能证明作者自述的资产数量，不能证明这些主题都适合 Koubo 或能避免模板化。
- 画面以高密度科技主题、演示卡片和屏幕录制为主；可以研究其信息层级，不复制主题、配色、线条、卡片、动效和页面布局。
- “禁用某一类视觉效果”不能被扩大为永久禁令。真正候选规则是：没有语义、证据或情绪目的时不使用；有明确目的时仍需最小样片验证。

## 4. M3：实时跟读的核心是分段时间映射和暂停保持

### 作者观点与画面证据

1. **简单短字幕可让动画时长匹配字幕段。**
   - 时间码：`00:33–01:06`。
   - 作者在剪映中为每一段字幕添加卡拉 OK 入场，并把入场动画拉到该段字幕长度。
   - 适用边界：只适合短段、停顿少、时间线已经准确切分的字幕。

2. **双层字幕可以表达“未读”和“正在读”。**
   - 时间码：`01:10–02:15`。
   - 作者复制字幕：底层降低透明度或改灰，作为未读全文；上层使用打字机或活跃层推进；中文字幕可保持静态。
   - 可迁移含义：一个低强调的稳定底层加一个按时间推进的活跃层，比整体位移更容易维持阅读位置。

3. **把连续动画平均铺满整段，会在朗读暂停时失去同步。**
   - 时间码：`02:24–03:05`。
   - 作者展示整段文章中语音发生中断或停顿时，字幕动画仍持续前进，直接造成音画不同步。
   - 这是本条最重要的失败样本：总时长相同不代表中间过程同步。

4. **在暂停点或句末切分，并让每段起止对齐对应语音。**
   - 时间码：`03:09–04:28`。
   - 作者把连续动画切成多个片段，逐段调整速度，使每段结束点与对应语音结束点一致，下一段从下一句朗读开始处继续。

5. **暂停区间保持上一状态，不继续推进。**
   - 时间码：`04:32–04:49`。
   - 作者用上一段末帧定格填补空隙；最终在 `04:51–04:57` 预览确认动画进度贴合朗读。
   - 可迁移原理是“分段时间映射 + 暂停保持”，不是剪映的复合片段、手动变速和定格操作本身。

### Koubo 迁移与反例

- Koubo 已有词级时间码时，不应先把字幕动画烘焙成视频再人工变速；应直接以 token 或短语的真实 `start/end` 驱动活跃层。
- 静音区间内保持上一个已读状态，下一 token 开始时再推进；不能按整个句子或整段的平均速度持续滚动。
- 当词级置信度不足、专名错误或说话重叠时，退化到短语级或句级；不得为了“逐字效果”伪造比转录证据更高的精度。
- 中文不一定需要逐字打字机。对于快速口播，短语级高亮可能比逐字闪动更稳定；具体粒度必须用真实口播样片评测。
- 不复制作者的剪映工程、字幕内容、字体、排版、复合片段、手动变速参数或教程镜头。

## 5. 官方能力边界与本地执行合同

### Remotion 官方能够证明什么

- [`renderMedia()`](https://www.remotion.dev/docs/renderer/render-media) 支持以 composition 的宽、高、帧率和帧数程序化渲染视频或音频；这证明可渲染，不证明某种审美或效率一定更优。
- [`useCurrentFrame()`](https://www.remotion.dev/docs/use-current-frame) 和 [`Sequence`](https://www.remotion.dev/docs/sequence) 提供逐帧时间和局部时间偏移，能够实现可寻址的镜头、字幕页和动画段。
- [`ThreeCanvas`](https://www.remotion.dev/docs/three-canvas) 将 React Three Fiber 与 Remotion 时间同步，并要求声明式、可暂停、可前后拖动的动画；这证明存在 3D 路径，不证明复杂 3D 比专用工具更省成本。
- [透明视频输出](https://www.remotion.dev/docs/transparent-videos/) 是官方支持的渲染路径，但 codec、像素格式、分块闪烁和播放器兼容性都需要单独验证。
- [`createTikTokStyleCaptions()`](https://www.remotion.dev/docs/captions/create-tiktok-style-captions) 的 token 包含绝对 `fromMs/toMs`；[官方展示示例](https://www.remotion.dev/docs/captions/displaying) 以 token 时间判断当前活跃词。这直接支持“按真实 token 时间推进”的实现方向。
- 官方资料没有给出“M1 能力表”的优先级，也没有证明标题中的营销比较、作者工作流效率或任何成片质量结论。

### HyperFrames 当前固定事实

- Koubo 当前训练链固定 HyperFrames `0.7.70`；升级探针、strict check、高质量渲染和完整解码已在两项原创沙盒及旧 `caption-pop` 入口上通过。
- 本地 composition 使用 HTML DOM 的 `data-*` 时间声明；每个 composition 只有一个暂停、可寻址的时间线，媒体播放由框架控制，同一时间必须得到同一像素。
- 媒体必须是宿主 composition root 的直接子级；禁止网络、未播种随机数、输入状态和异步时钟决定渲染结果。
- 当前教程沙盒已审计八种 primitive：`caption-pop`、`keyword-emphasis`、`pause-aware-follow-caption`、`element-slide`、`element-bounce`、`semantic-layout-router`、`sfx-cue`、`voice-pause`。新增的两种专项 Motion primitive 已完成独立复刻与 proof 验证，但通用复刻入口仍拒绝为其自动写入 `recreated` transition。

### 引擎选择含义

- 已批准训练规格明确规定：HyperFrames 和 Remotion 都是可选执行引擎，不预设默认和对照身份；Director 应按同步精度、组件复用、确定性、画幅、性能、兼容性、真实渲染结果和回滚成本逐镜头选择。
- M1 的作者经验可以丰富引擎能力问题清单，但不能替代 Koubo 的镜头级证据路由。
- `config/video_workflow_v4.json` 当前仍保留历史字段 `defaultEngine: hyperframes`，而新训练规格已经取消训练阶段的默认/对照身份。这是“批准的设计与当前生产配置尚未同步”，不是本报告可以静默修改的配置错误；本批次不改生产默认、不改 v4 回退关系。
- 若两条路径都可能适用，应先用同一素材做最小镜头样片，再比较真实同步、可读性、渲染稳定性、开发成本和降级路径。

## 6. 三条互补候选技巧

以下名称和规则是 Codex 的跨视频抽象，不是三位作者的原始命名。数量限制为三条，分别覆盖 Caption、Motion 和 Director；全部保持 `Candidate`。

### caption-technique.pause-aware-follow-caption.v1

- **问题**：字幕段总时长正确，但停顿时高亮仍前进，造成观众看见的阅读进度领先于声音。
- **候选规则**：渲染低强调的稳定底层和按 token/短语真实时间推进的活跃层；语音暂停区间保持上一状态，下一 token 开始时再继续。低置信度时退化到短语或句级。
- **证据**：M3 `01:10–02:15`、`02:24–04:57`；Remotion 官方 token `fromMs/toMs` 展示能力。
- **适用条件**：已有可信词级或短语级时间码，字幕长度和安全区通过排版检查。
- **禁用/退化条件**：转录置信度不足、多人重叠、极快口播或逐字闪动降低可读性时，不强行逐字；改用短语或句级高亮。
- **现有 primitive 映射**：`keyword-emphasis` 只能部分覆盖活跃词强调，`caption-pop` 只能覆盖入场；暂停保持和 token 时间映射需要新的受审计 primitive 或对现有 primitive 的版本化扩展。
- **验证方式**：原创 8–12 秒口播样片，包含至少两次可听见停顿；逐帧检查停顿区间字幕状态不推进，并与实际词级时间码对齐。

### motion-technique.semantic-layout-router.v1

- **问题**：动效系统先选模板或入场动画，再把字幕硬塞进去，导致重复、拥挤、剧透或真实证据被装饰遮盖。
- **候选规则**：先标记当前语义角色和信息密度，再选择画面结构：单重点 → 大标题/关键词/中心卡；步骤 → 列表/流程/步骤卡；证据 → 真实录屏/截图 + 解释卡/箭头/标签；信息过密 → 拆场景。进入动画最后选择，且不能提前出现后文信息。
- **证据**：M2 `01:35–03:17`、`04:18–05:47`；M1 `03:20–03:51` 的真实地图数据边界。
- **适用条件**：稿件或逐字稿已稳定，并能区分重点、步骤、证据、结果和补充说明。
- **禁用/退化条件**：没有足够真实证据时，不生成伪截图、伪数据或假操作；宁可保持真人主画面和简短字幕。
- **现有 primitive 映射**：`element-slide`、`element-bounce` 只能承担进入方式，不能承担语义选型；需要新的组合配方/路由 primitive，并允许其最终调用现有进入 primitive。
- **验证方式**：对同一段真实口播生成语义标注和一个结构方案；检查无提前剧透、无完整字幕重复、证据与解释角色分离，并由用户判断画面是否帮助理解。

### director-technique.plan-preview-promote-gates.v1

- **问题**：引擎或 Agent 从一句模糊需求直接生成全片，并把一次成功自动写成默认规则，导致返工和未经批准的知识固化。
- **候选规则**：先讨论镜头方案，再逐镜头实现和自检；主题/比例、预览成片、经验晋升分别设置独立人工门。Director 对每个镜头选择 Remotion、HyperFrames、FFmpeg 或组合路径，并记录选择与回滚理由。
- **证据**：M1 `01:46–02:13`、`05:51–06:28`；M2 `03:18–04:08`。
- **适用条件**：存在实质性的视觉、比例、引擎或审美分叉，且全片包装成本明显高于最小样片。
- **禁用/退化条件**：编码、画幅、安全区等确定性技术约束不需要审美选择题；但仍须通过技术 QA。
- **现有 primitive 映射**：这不是单一画面动画，现有六种渲染 primitive 均不能覆盖；应作为新的 Director 编排 primitive/权限合同，渲染时再组合已审计的 Caption、Motion 和 Sound primitive。
- **验证方式**：场景决策测试验证三个确认门彼此独立；Director 不输出批准、发布或记忆晋升字段；引擎选择包含可审计证据和失败回退。

## 7. 当前结论与后续门槛

- M1 最适合补充“逐镜头生产流程、参数化预览和引擎边界”，不适合把作者能力表直接写成官方路由。
- M2 最适合补充“语义时间轴、信息密度路由、预览 QA 和人工判断门”，不证明其自有 Skill 已被独立复刻。
- M3 最适合补充“暂停感知的跟读字幕”，应迁移时序原理，不迁移剪映的手工复合片段、变速和定格操作。
- 三条候选技巧作用互补：一条解决字幕微观时序，一条解决语义到画面结构，一条解决跨 Agent、引擎和权限的生产编排。
- M1/M2 已完成原创 HyperFrames 沙盒与媒体技术 QA，M3 已完成声明式场景验证；没有复制来源代码或资产，没有写入 Agent 运行知识，也没有修改生产配置。
- 下一步先完成第二级候选审核。只有明确保留的具体条目才取得真实片段试用准入；真实口播评测通过仍不等于正式知识晋升。
