## 结论摘要

三条来源形成了一条互补链路：

1. C1 回答“观众为什么值得看”：内容至少要给出一个可辨认的观众收益，而不是仅展示创作者做了什么。
2. C2 回答“为什么会自嗨”：头像、简介、选题和开头已经形成观众预期，后文即使信息本身有价值，若不兑现这份预期，仍然是错配。
3. C3 回答“怎样保留创作者本人”：根据上镜熟练度选择自由练习、大纲表述或逐字稿，并优先从本人真实对话中提取语言，而不是强迫其念通用文案。

### 可迁移判断

- Content Strategist 不应只问“用户想分享什么”，还要问“观众看完具体多了什么能力、理解、情绪确认或可期待的变化”。
- 普通观众价值必须具体到一个人、一个场景或一个小问题；“有干货”“有价值”不是可验证答案。
- 宽赛道不是自动否决项，但必须解释相对既有内容的服务对象、证据或问题粒度差异。
- Ordinary Viewer Critic 可以尖锐追问：“如果删掉创作者姓名，这条内容除了记录自己，还替我解决了什么？”

### 适用边界与反例

- 一条视频不需要同时满足四类收益；某些优秀内容只完成其中一项。
- 纯娱乐、审美体验、陪伴和社群归属也可能形成价值，不能被狭义“解决问题”排除。
- 热门赛道仍可能通过独家证据、鲜明视角、极强表达或新受众切片建立差异，不能机械要求所有人转向小众。
- 同赛道创作者的互动不一定无效；它只是不能单独证明目标普通观众愿意持续观看。

### 无法由视频证明的自述或强结论

- “四项一条都不占就不必做自媒体”是作者的修辞性判断，不是平台规律。
- “坚持发布不会被看见”“普通人不能进入拥挤赛道”没有对照数据或长期样本。
- 示例没有展示改造前后的真实完播、收藏、转化或受众反馈，不能直接得出效果因果。

### 可迁移判断

- Strategist 在访谈结束前应写出一句“观众需求合同”：谁因为哪一个具体问题进入，视频承诺让他得到什么。
- Hook 不是独立的吸睛句；它会产生后文必须偿还的内容债务。
- 每个主要段落都应能说明自己如何推进承诺。与主题无关的好信息仍可能应该删除或另开一条。
- Ordinary Viewer Critic 应区分“信息本身有价值”和“它对这一刻的我有价值”。

### 适用边界与反例

- 不应把“全程有价值”误写成每秒塞新知识；必要停顿、故事、铺垫和情绪变化也可以服务同一承诺。
- 身份不能替代证据。居家照护者可能确有商业成果，年轻人也可能有可验证经历；Critic 应审查证据与主题匹配，而不是依赖刻板印象。
- 视频可以有转折或扩大主题，但要提前建立新的桥梁，不能突然换一套观众需求。
- 一个账号允许多种内容合同；本原则约束单条视频内部一致性，不强迫账号永久只讲一个问题。

### 无法由视频证明的自述或强结论

- “大部分人做不起来是因为不知道核心卖点”没有样本和排除其他原因。
- “从头到尾都必须感到价值”没有留存曲线或对照实验支持。
- 身份错位例子只说明作者的直觉，不能证明观众必然滑走。

### 可迁移判断

- Content Strategist 与用户的访谈不是写稿前的形式步骤，而是“本人语言语料”的主要来源。
- 脚本形态应根据表达准备度选择：私下自由练习 → 大纲与本人复述 → 表达稳定后可选逐字稿；不能把一种方式设为所有人的硬规则。
- Script Agent 应优先重组用户已经说过的观点、措辞和具体经历，并明确哪些句子是 AI 新写的连接语。
- Ordinary Viewer Critic 可以检查“这像一个真人在说，还是像作者第一次看到一段陌生文案”。

### 适用边界与反例

- 提词器并非天然有害。法规、医学、数据、品牌口径、非母语表达或无障碍需求可能要求更精确的逐字稿和辅助提示。
- 不写稿的松弛练习适合作为私下训练，不代表未核验的即兴内容可以直接发布。
- 本人原话仍可能冗长、事实错误或包含隐私，需要结构整理、事实核验和授权边界。
- “听起来自然”不能替代受众价值；口语化稿件仍须满足 C1 的观众收益和 C2 的承诺兑现。

### 无法由视频证明的自述或强结论

- “五年服务粉丝千万、百万的头部创作者”是作者自述，本轮未独立核实客户、年限和结果。
- 没有 A/B 样本证明大纲、逐字稿、提词器或复述法哪一种普遍带来更高留存或转化。
- “表达状态有时比内容更重要”只能作为待验证假设，不能压过事实准确性和观众收益。

## 跨来源综合

三条视频不是三个互相独立的技巧，而是三个连续判断：

```text
观众收益是什么（C1）
→ 开头形成了什么具体期待（C2）
→ 如何用创作者本人的语言兑现期待（C3）
```

对当前 Koubo 工作流的直接影响应是：

- Strategist 在生成任何成稿前，先取得“目标观众、当下问题、单条承诺、真实证据、用户本人表述”。
- Script Agent 不从抽象方向直接扩写标准 AI 文案，而是把已确认的观众合同与本人语料组织成结构。
- Ordinary Viewer Critic 在稿件和成片阶段都可以从三处发难：我为什么在意、开头欠我的东西还了吗、这真像创作者本人吗。
- 三者仍不能决定标题、发布、留存或生产批准，也不能自动替换用户方向。

## 新候选原则

以下仅是待复刻、待评测、待用户第二级审核的候选，不修改 `config/multi-agent/content-principles.json`。

### 1. `content-principle.one-primary-audience-payoff.v1`

- 状态：`candidate`
- 来源：C1，00:00–00:18、02:17–03:26。
- 候选主张：单条内容至少要明确一个主要观众收益；记录创作者做了什么，不等于观众获得了什么。
- Strategist 行为：要求用一句可验证的话补全“目标观众看完后，能解决、理解、确认、感受或尝试什么”。
- Ordinary Viewer 检查：删掉作者姓名和项目名后，我还能说出自己得到了什么吗？
- 适用：项目分享、AI 实践复盘、教程、经验型口播。
- 反例与边界：纯审美、娱乐、陪伴内容可以选择情绪或身份收益；不要求四类收益全占。
- 晋升前验证：用同一真实方向分别生成“创作者记录版”和“单一观众收益版”，让用户及普通观众盲评是否更值得继续听。

### 2. `content-principle.opening-creates-audience-contract.v1`

- 状态：`candidate`
- 来源：C2，00:21–01:41。
- 候选主张：标签、题目和开头会形成一份单条视频的观众需求合同；后续的每个主要段落都应推进或兑现它。
- Strategist 行为：在写稿门前输出“谁因为什么进入、期待得到什么、结尾如何证明兑现”。
- Ordinary Viewer 检查：这段即使有价值，是否是我点进这条视频时要的东西？
- 适用：强钩子口播、问题解决型内容、系列首集、项目结果展示。
- 反例与边界：允许必要故事、停顿和主题升级，但必须有清楚因果桥；不能把高密度误解为持续塞信息。
- 晋升前验证：对既有真实稿件标注每段与开头合同的关系，检查删去错配段后是否更清楚，同时避免损失情绪和可理解性。

## 旧作品超出最近 20 条时的只读冻结方法

以下是本轮可复用的命令骨架，不包含 Cookie、签名 URL、`msToken`、`a_bogus` 或其他登录数据。所有中间输出必须留在显式 `%TEMP%` 目录，不能写入仓库根目录。

```powershell
$profile = '<opencli-profile>'
$session = "douyin-reference-$videoId"
$tempDir = Join-Path $env:TEMP "koubo-agent-training\$videoId"

opencli --profile $profile browser $session open "https://www.douyin.com/video/$videoId" --window background
opencli --profile $profile browser $session wait time 12

# 1. 从可见 DOM 核对作者、时长、标题和互动快照。
# 2. 在同一个浏览器会话中读取 performance resource entries。
#    PowerShell 下应先把 JS 做 Base64，再执行 eval(atob(...))，避免 >、<、|、& 被 cmd 包装器解释。
# 3. 完整签名媒体 URL 只保留在当前进程变量中，不打印、不落盘。
# 4. 选择与目标详情页相符的 media-video / media-audio 资源后，只下载到 $tempDir。

Invoke-WebRequest -Uri $videoUrl -OutFile $tempVideo -Headers @{
  'User-Agent' = 'Mozilla/5.0'
  'Referer' = 'https://www.douyin.com/'
}
Invoke-WebRequest -Uri $audioUrl -OutFile $tempAudio -Headers @{
  'User-Agent' = 'Mozilla/5.0'
  'Referer' = 'https://www.douyin.com/'
}

ffmpeg -y -i $tempVideo -i $tempAudio -map 0:v:0 -map 1:a:0 -c copy -movflags +faststart $mediaFile
Get-FileHash -LiteralPath $mediaFile -Algorithm SHA256
opencli --profile $profile browser $session close
```

建议修复 `fetch_douyin_reference.mjs` 时增加：

- 作者最近 20 条未命中后，进入公开详情页 fallback，而不是直接失败；
- `web read` 导航拒绝后，改走命名 browser session 的 `open → wait → DOM/resource` 链；
- 媒体选择同时校验作者、目标视频 ID、可见时长和解码结果，不能只取第一个 CDN 资源；
- DASH 音轨在转录前检查时间戳空洞，必要时先用 `aresample=async=1:first_pts=0` 生成对齐 PCM；
- 继续禁止持久化 Cookie 和签名播放 URL，并让 source metadata 记录 fallback 原因。
