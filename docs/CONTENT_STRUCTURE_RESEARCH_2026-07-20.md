# AI行动类口播结构调研｜2026-07-20

## 1. 调研目标与边界

本次调研服务于账号“从知道到做到｜普通人的AI行动实验”。目标不是抄热门文案，而是找出同类内容中可复用的：

- 问题如何被命名；
- 证据在什么位置出现；
- 方法如何变成值得收藏的信息；
- 观众如何判断“这条与我有关”；
- 结尾如何推动一个真实动作。

数据为 2026-07-20 页面可见值，平台计数会继续变化。抖音样本的数据与正文已核验；小红书搜索被登录页拦截，无法可靠核验正文、点赞和收藏，因此不把小红书结果伪装成高赞高藏样本。

## 2. 指定视频拆解

**视频：** [《第103集｜大部分人的第一桶金，都没那么“干净”》](https://www.douyin.com/video/7644222320244697787)

**作者：** 百万钱叔
**时长：** 3分40秒
**发布：** 2026-05-27
**页面数据：** 约2.1万赞、673评论、1.8万收藏、4930分享
**收藏/点赞：** 约86%

### 2.1 真正的核心

表面主题是“模仿是否丢人”，深层交付的是一套从模仿到形成个人优势的方法：

1. **拆透逻辑**：先看目标人群、真实需求、信任如何建立、最后如何形成结果，而不是只看表面话术。
2. **复刻结构**：复用已经被验证的叙事顺序和业务顺序，缩短从零摸索的距离。
3. **打造特色**：结构跑通之后，再加入自己的经历、能力、约束和表达，形成不可替代的版本。

这里的“复刻”不是复制原句。可迁移的是“问题顺序 + 证据位置 + 信息交付方式”，不可迁移的是别人的事实、案例、措辞、标题和人设。

### 2.2 视频为什么让人收藏

它不是直接抛出三条方法，而是先解决观众对“模仿”的道德抵触，再用故事和结果建立信任，最后给出一张可截图的方法图。

结构顺序为：

1. **道德冲突钩子**：把观众不愿承认、但确实存在的矛盾说出来。
2. **个人失败**：证明作者不是站在终点说教。
3. **具体拆解或他人干预**：指出原先到底错在什么地方。
4. **前后结果证据**：用可核验变化证明干预有效。
5. **第二个外部案例**：避免方法只对作者本人有效。
6. **三层框架**：把故事压缩成可以保存、复用的判断工具。
7. **情绪释放 + 最小行动**：解除“模仿等于没本事”的心理负担，让观众愿意先做起来。

**关键判断：** 约86%的收藏/点赞比，不只是因为故事有共鸣，而是“共鸣负责看下去，证据负责相信，框架负责收藏，最小动作负责开始”。

## 4. 样本共同规律

### 4.1 钩子不是夸张，而是精准重命名

弱钩子：

> AI工具太多了，今天教你怎么学。

强结构：

> 你学AI不是学得慢，是把收集工具当成了学习。

它同时完成三件事：指出具体行为、推翻旧解释、引出新的判断标准。

### 4.2 个人经历只承担“证据角色”

高质量个人故事不会停在“我做了什么”，而会回答：

- 这个失败证明了哪个常见判断是错的；
- 哪个动作带来了变化；
- 观众如何判断自己是否遇到同一问题；
- 方法在哪些情况下还不能下结论。

### 4.3 收藏来自“动作 + 完成信号”

只有动作还不够：

> 找一个真实问题，做起来。

更可执行的写法是：

> 写下最近一周重复遇到的一件麻烦，只选其中十分钟能验证的一步；当你得到一个文件、一次测试结果或一个明确报错，就算完成第一轮。

前半句是动作，后半句是完成信号。观众知道何时开始，也知道何时停下来判断。

### 4.4 先让观众定位自己，再给唯一下一步

路径类内容表现好的原因，不只是列了三到五步，而是观众能回答：

- 我现在在哪一阶段；
- 当前最大的阻塞是什么；
- 下一步只做哪一件事；
- 做完以后看什么信号。

### 4.5 结尾只保留一个主动作

“做一个任务 + 回答一个问题 + 等下一集验证”三个意图都可以策划，但连续念出来会像运营指令。口播应从中选一个与本集最匹配的主动作，另外两个可融入正文或平台文案。

## 5. 三种可复用结构

### 5.1 evidence-story｜证据故事

**适用：** 有真实失败、干预动作、前后结果或可核验证据。

1. 精准矛盾或反常识钩子；
2. 观众正在付出的具体代价；
3. 个人失败或外部案例；
4. 关键动作与前后结果；
5. 2—4项可执行框架；
6. 适用边界；
7. 一个最小行动。

**账号示例题材：** “我给口播工作台加了更多功能，为什么反而更难拍第一条？”

### 5.2 saveable-map｜可收藏路径图

**适用：** 观众不是没信息，而是不知道先后顺序或自己处于哪一阶段。

1. 精准命名混乱；
2. 承诺一张3—5阶段路径；
3. 每阶段给“问题、动作、完成信号”；
4. 让观众完成自我定位；
5. 只给当前阶段的下一步。

**账号示例题材：** “普通人第一次用AI做真实项目，不要先学完工具：四个阶段判断你卡在哪。”

### 5.3 short-resonance｜短共鸣

**适用：** 只有一个高共识焦虑、一个自我识别判断和一个立刻可做的动作。

1. 一句共识焦虑或反差；
2. 让观众识别自己的阶段或错误；
3. 一个动作；
4. 一个验证信号；
5. 自然收束。

**账号示例题材：** “收藏了五十个AI工具，还没有一个能展示的结果，你缺的不是第51个。”

## 6. 生成器落地规则

未来口播包新增 `structureDesign`：

```json
{
  "structureDesign": {
    "archetype": "evidence-story|saveable-map|short-resonance",
    "selectionReason": "为什么本题适合这套结构",
    "coreQuestion": "整条视频只解决的一个问题",
    "hookConflict": "精准矛盾或代价",
    "saveableFramework": [
      {
        "label": "阶段或步骤",
        "action": "可执行动作",
        "expectedSignal": "完成后可观察信号"
      }
    ],
    "personalEvidenceRole": "个人经历只负责证明什么",
    "personalVariation": "本账号真实场景带来的变化",
    "boundary": "适用边界",
    "payoff": "观众看完能完成什么判断或行动"
  }
}
```

生成质量门禁：

- 原型只能是三种之一；
- evidence-story 需要2—4个框架项；
- saveable-map 需要3—5个框架项；
- short-resonance 需要1—2个框架项；
- 每项必须有名称、动作和可观察信号；
- 必须说明个人证据作用、个人变化、适用边界和观众回报；
- 继续执行既有事实门禁，证据没有的数字、结果和承诺一律不能写；
- `commentPrompt`、`viewerTask`、`followPromise` 保留为策划意图，口播结尾只自然使用一个 `primaryClose`；
- 只借鉴结构，不复刻任何样本文案。

## 7. 小红书限制与复查路径

本次通过平台搜索尝试检索“普通人学AI”“AI学习”“AI入门”“AI工具收藏”等同类词，但搜索结果要求登录；当前可用工具也没有已授权的小红书连接。因此：

- 不声称已核验任何小红书笔记的高赞、高收藏排名；
- 不使用旧的宽泛AI趋势样本代替本次同类样本；
- 抖音验证结论作为当前生成器的主要证据；
- 登录可用后，至少复查10条同类小红书视频笔记，并记录标题、正文、点赞、收藏、评论、发布时间、结构和截图时间；
- 只有页面可见数据核验后，才比较小红书与抖音在封面、标题、信息密度和结尾动作上的差异。

## 8. 本轮结论

这个账号不该追求“每条都讲得很完整”，而应追求“每条只解决一个问题，并让观众知道下一步怎么做、做到什么算有结果”。

之后的核心写作顺序是：

> 先拆透观众问题 → 选择合适结构 → 用真实证据建立信任 → 把方法写成动作与信号 → 加入个人真实变化 → 一个动作自然收束
