# Codex / Agent / Skill 证据来源矩阵

## 一、主线证据

| 优先级 | 来源 | 能证明什么 | 使用方式 | 限制 |
|---:|---|---|---|---|
| 1 | 官方文档、官方仓库、Release和许可证 | 来源、版本、功能与法律边界 | 显示链接、版本和关键条款 | README自述不等于真实可用 |
| 2 | 本机安装、调用和测试结果 | Windows环境能否跑通 | 展示脱敏命令、输入输出和验收 | 不公开密钥、Cookie和私人路径 |
| 3 | 失败日志与修复差异 | 常见坑、恢复方式与边界 | 展示最小错误片段和前后差异 | 不暴露安全细节和第三方隐私 |
| 4 | Skill、Agent和工作流产物 | 是否能产生可复用结果 | 展示提示词、流程图、清单和模板 | 必须说明版本和适用范围 |
| 5 | 源码、依赖和维护记录 | 安全、维护、兼容性和退出成本 | 形成审计表和采用建议 | 时间敏感，发布前复核 |
| 6 | 真实观众问题和资源领取 | 哪类资产真正有需求 | 匿名汇总，不复制私人信息 | 没有真实数据时保持为空 |

## 二、证据等级

- **E1 直接运行证据**：命令、测试、输入输出、截图、生成文件和前后对比。
- **E2 源码与项目证据**：仓库关系、依赖、提交、Release、许可证和维护活动。
- **E3 官方事实**：产品文档、API文档、公告和条款。
- **E4 用户报告**：Issue、讨论、评论和第三方案例，只能作为风险或需求线索。

主选题至少需要一项E1；开源审计同时需要E2或E3。E4不能单独支撑结论。

## 三、研究顺序

创建或推荐 Agent、Skill、工作流和基础组件前，按以下顺序选择：

1. 直接复用；
2. 适配；
3. 组合；
4. fork；
5. 最小自建。

每个候选至少检查功能、许可证、安全、维护、真实案例、Windows兼容性、隐私和退出成本。

## 四、公开内容来源

| 来源 | 主要用途 | 必须核验 | 不得做什么 |
|---|---|---|---|
| GitHub / 官方仓库 | Skill、Agent和开源库发现 | repo关系、license、release、commit | 只读README就推荐 |
| 官方文档 | API和安装事实 | 日期、版本、适用平台 | 使用过期文档冒充当前事实 |
| Issue / Discussion | 真实失败与维护风险 | 是否可复现、是否已修复 | 把单个报告写成普遍事实 |
| 抖音等公开视频 | 问题表达、结构和互动发现 | 至少一条完整内容 | 复制文案、案例和素材 |
| 本地项目 | 实测与可交付资产 | 脱敏、所有权、运行结果 | 公开公司或客户内容 |

## 五、资源交付证据

每个提示词、流程图、清单或模板必须记录：名称、版本、生成日期、包含文件、适用对象、已验证环境、限制和领取入口。视频发布前必须确认资源真实存在。

## 六、故障与安全

外部来源失败时停止声称已核验；页面受阻时标记不可用，不推断正文。任何截图、日志和文件公开前检查密码、API Key、Token、Cookie、私钥、邮箱、手机号、私人聊天、客户数据、精确路径、未公开仓库和内部域名。
