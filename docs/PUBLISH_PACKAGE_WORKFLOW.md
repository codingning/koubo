# 成片到发布素材包工作流

状态：Ready

## 任务理解

- 目标：把一次真实口播从原片处理、样片审核、全片返修和最终 QA，继续延伸到可人工发布的完整素材包。
- 使用者：三金本人；工作台负责生成、预览、修改和下载，不连接任何平台账号。
- 交付物：审核通过的成片、3 个标题候选、抖音/小红书/视频号发布文案、6—10 个关联话题、9:16 手机封面、16:9 横版封面和 ZIP 素材包。
- 完成标准：所有发布产物绑定同一个最终成片版本；旧成片、旧封面和旧发布素材包均不覆盖；页面可编辑、复制、重新生成和下载。

## 标准流程

1. 锁定选题、证据和口播稿。
2. 上传原片，在本地完成转录、剪辑计划和人声处理。
3. 审核关键帧，只确认构图、字幕层级和素材方向。
4. 审核 15—25 秒动态样片，未批准不生成全片。
5. 渲染完整成片并执行视频、音频、字幕、素材与封面 QA。
6. 根据自然语言反馈生成新版本，旧版本继续保留。
7. 用户点击“审核通过”，最终审核记录绑定成片版本、媒体哈希、审核预览和素材清单。
8. 工作台自动在本地生成发布素材包，并进入“发布准备”页面。
9. 用户选择或修改标题，编辑各平台文案和话题；标题变化时只重做封面，不重渲染视频。
10. 用户复制单个平台文案，或下载 ZIP 后自行登录平台发布。

## 发布素材包结构

每个最终成片版本生成独立文件：

```text
video-jobs/<job-id>/
├─ final-vN.mp4
├─ final-review-vN.json
├─ publish-package-vN.json
├─ publish-copy-vN.md
├─ publish-package-vN.zip
└─ covers/vN/
   ├─ cover-vN-9x16.png
   └─ cover-vN-16x9.png
```

ZIP 只包含发布文案、结构化 JSON 和封面，不重复打包体积较大的最终视频；视频仍通过成片下载按钮获取。

## 封面规则

- 默认风格：真人像占主体，加 2—3 行大文本。
- 白字为主，最多使用一种黄色突出关键词。
- 不再叠加工作台截图、流程卡、标签和说明块。
- 9:16 用于手机信息流；16:9 用于横版列表、视频号或其他横版入口。
- 封面只从本地原片帧生成，不上传真人照片，也不使用生成模型重画人脸。

## 发布文案规则

- 提供 3 个标题角度：结果直给、问题钩子、过程复盘。
- 抖音：短钩子、真实过程、一个评论问题。
- 小红书：分点说明过程和真实感受，避免把计划写成结果。
- 视频号：表达更完整、克制，强调真实过程与人工审核。
- 每个平台生成 6—10 个相关话题；话题必须来自稿件、工具或真实制作过程。
- 不自动发布、不自动评论、不保存平台 Cookie 或账号凭据。

## 版本和权限边界

- 发布素材包必须绑定当前最新版成片，历史页面不能修改最新版。
- 成片 QA 未通过时不能最终审核，也不能生成正式发布素材包。
- 修改标题或封面不会修改成片媒体哈希。
- 每次返修形成新成片版本；每个版本使用独立的 `publish-package-vN.*` 文件。
- 工作台只提供生成、修改、复制和下载；实际上传和发布始终由用户完成。

## 工作台接口

- `POST /api/jobs/:id/approve`：最终审核通过，并自动生成发布素材包。
- `POST /api/jobs/:id/publish-package`：保存修改或重新生成素材包；必须携带当前 `expectedVersion`。
- `POST /api/jobs/:id/cover`：只重做封面，不重渲染视频；已审核任务会同步更新发布 ZIP。

## 验收检查

- 审核通过后自动出现“发布准备”页面内容。
- 标题候选数量为 3。
- 平台包含抖音、小红书和视频号。
- 关联话题数量为 6—10。
- 9:16 与 16:9 封面可预览、可下载，均为真人大字简洁风格。
- 修改最终标题后，封面同步更新，视频文件不变。
- JSON、Markdown 和 ZIP 均可下载。
- 再次批准同一版本不会重复生成不同的最终审核记录。
- 页面和服务端均保持 `autoPublish=false`。
