# Koubo 受控多 Agent 创作与记忆系统设计

日期：2026-07-23  
状态：设计已获用户认可；尚未授权实施

## 任务简述

状态：Ready

### 任务理解

- 目标：让 Koubo 在保持账号一致性的同时，持续积累字幕、动效、声音和配音编排经验，通过独立创作与质检逐步发现品牌骨架。
- 用途：用户本人持续生产“从知道到做到”的 AI 使用结果型口播视频。
- 交付物：受控多 Agent 架构、两条主流程、一条记忆治理闭环，以及未来实施的验收标准。
- 完成标准：能够解释知识如何进入系统、Agent 如何协作、经验如何验证和晋升、品牌如何发现，以及如何避免错误记忆和风格失控。

### 已确认

- 当前成片没有明显质量问题，改造动机是避免长期固定模板化和无法积累创作能力。
- 账号风格需要稳定，但视觉与声音品牌骨架尚未形成。
- 前 10～20 条视频作为品牌发现期，允许主动探索不同字幕、动效和声音组合。
- 前期不以模型调用和渲染成本为主要约束。
- 发布前以用户审核、返修意见和逐秒审片为主要学习信号；发布后使用留存、完播、重复播放和互动数据校准。
- 用户认可“确定性总控 + 专家 Agent 创作组”，不采用完全自治的 Agent 群。
- 用户认可“知识摄取流程 + 视频生产流程 + 评测与记忆治理闭环”。
- 新建 Agent、Skill、工作流或记忆组件前，必须优先检索 GitHub 和官方生态中已有的成熟开源方案，不默认从零自建。

### 权限边界

- 本文只固化设计，不修改 Koubo 生产代码，不迁移现有任务，不调用付费服务，不上传私人素材。
- 后续必须先形成并审核实施计划，才能开始代码改造。

## 一、为什么需要受控多 Agent

当前 `visual-director-v4` 已经具备阶段拆分、结构化产物、版本保留和人工审核门，适合继续作为可靠的执行骨架。它不足的地方不是“不能生成成片”，而是：

1. 创意主要由同一个模型入口按固定提示词生成，候选容易趋同。
2. 生成者同时承担大部分自检，缺少真正独立的专业质检。
3. 历史成片、返修和审核被保存为档案，但没有转化为下一次可检索、可评分的创作经验。
4. 字幕、动效、声音和配音编排缺少独立资产身份、适用条件与失败边界。
5. 当前默认视觉系统容易长期固化为模板，而不是形成有边界的品牌语言。

因此需要引入多 Agent，但只在创意分歧、专业判断和独立质检处使用。时间轴、文件、版本、渲染、技术 QA 和审核门继续由确定性程序负责。

## 二、总体架构

```text
真人原片 / 内容目标 / 外部教程 / 历史反馈
                    │
                    ▼
         确定性证据与工作流总控
     ASR、抽帧、镜头变化、音频事件、版本
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
   知识摄取流程          视频生产流程
          │                   │
          └─────────┬─────────┘
                    ▼
        评测、记忆治理与品牌发现
                    │
                    └──→ 下一次检索与提案
```

### 设计原则

- 程序负责事实，Agent 负责解释、提案和评价。
- 专家先独立作答，再由批评 Agent 盲评，避免互相锚定。
- Agent 的记忆存放在外部本地系统中，不依赖模型隐式记忆。
- 一次使用不等于学会；一次胜出不等于品牌骨架。
- 所有建议必须能追溯到来源、时间码、输入版本和评测证据。
- 用户在品牌发现期拥有最终审美决定权和长期记忆否决权。

### 开源复用优先门禁

任何 Agent、Skill、工作流、记忆框架、评测器或媒体处理组件进入自研设计前，必须先完成一次可追溯的能力发现：

1. 优先搜索项目官方文档、官方仓库、GitHub 和可信插件/Skill 目录。
2. 用同一份需求清单评估候选，而不是先选技术再迁就需求。
3. 至少记录：
   - 功能覆盖和与 Koubo 的接口匹配度；
   - 开源许可证及商业使用边界；
   - 最近维护时间、发布节奏、维护者和社区活跃度；
   - 测试、真实案例、使用者反馈和已知问题；
   - 安全记录、依赖树、安装脚本和供应链风险；
   - Windows、本地运行、现有模型、HyperFrames/FFmpeg 和数据格式兼容性；
   - 是否会上传原片、转录、记忆或其他私人数据；
   - 接入、维护、替换和退出成本。
4. 决策顺序固定为：

```text
直接复用成熟方案
→ 通过适配层集成成熟方案
→ 组合多个边界清晰的组件
→ fork 并维护必要改动
→ 只有在以上均不满足时才自建
```

5. “开源”不等于“完善”或“安全”。候选必须先在隔离环境进行代码审计、依赖检查和本地验收，不能直接进入生产工作流。
6. 采用第三方方案必须固定版本、保存来源和许可证、记录本地修改，并保留替换或回退路径。
7. 若最终选择自建，设计记录必须说明检索过哪些候选、为何不满足，以及自建范围为何是必要的最小范围。

## 三、角色与边界

### 1. 确定性工作流总控

它不是创意 Agent，职责包括：

- 冻结每次任务输入和版本；
- 执行 ASR、逐秒抽帧、镜头变化检测和音频事件分析；
- 按职责分发最小必要上下文；
- 管理并发、超时、重试和失败降级；
- 保存候选、评语、时间码和使用的记忆版本；
- 执行关键帧、短样片、完整成片的审核门；
- 调用 HyperFrames、FFmpeg 和技术 QA。

### 2. 视觉语言 Agent

- 负责画面构图、人物位置、证据画面、颜色和信息层级。
- 私有记忆保存视觉案例、适用内容、人物安全区和失败条件。
- 不决定字幕断句、声音响度或最终品牌晋升。

### 3. 字幕排版 Agent

- 负责字幕断句、字号、字体身份、位置、关键词强调和阅读节奏。
- 区分逐字字幕与信息卡，禁止把同一句话重复排版冒充信息设计。
- 私有记忆保存字幕技巧卡、适用语义、速度范围和可读性结果。

### 4. 动效 Agent

- 负责进入、退出、强调、转场、运动曲线和元素时序。
- 每个动效必须说明服务的语义目的，不以“持续变化”作为唯一价值。
- 私有记忆保存时间曲线、持续时间、依赖元素和冲突条件。

### 5. 声音 Agent

- 负责 BGM、音效、配音重音、停顿、声音落点和人声避让。
- 音效必须记录功能、授权来源、响度范围和与画面事件的时间关系。
- 不直接改写口播内容。

### 6. 留存质检 Agent

- 基于逐字稿、每秒帧、镜头变化和音频事件，逐段回答“观众此刻为什么继续看”。
- 它检查的是观看理由，不要求每秒新增文字、转场或音效。
- 必须引用具体时间码，区分低信息、必要停顿和情绪留白。

### 7. 独立批评 Agent

- 在不知道方案作者的情况下盲评候选。
- 使用固定但版本化的评分标准，明确提出反对意见和风险。
- 不负责生成新的完整方案，避免评价与创作再次混为一体。

### 8. 总导演 Agent

- 汇总专家提案和批评意见，保留冲突而不是强行一致。
- 组合出少量差异明显、能被比较的关键帧和短样片候选。
- 不能绕过人工审核门，也不能自行把经验写入品牌骨架。

### 9. 品牌档案 Agent

- 维护品牌假设、支持证据、反例、置信度和适用范围。
- 发现稳定模式，但不把单条视频表现直接解释为品牌结论。
- 只能提出晋升、降级或过期建议；最终品牌骨架由用户确认。

## 四、流程 A：知识摄取

当用户提供包含多种字幕、动画、音效或配音玩法的教学视频时：

1. **来源登记**
   - 保存作者、链接或本地路径、内容版本、文件哈希、版权与学习边界。
   - 原视频和完整转录只在共享证据层保存一份，不复制到多个 Agent。

2. **确定性预处理**
   - 生成逐字稿、章节、时间码、每秒帧、变化关键帧和音频事件时间线。
   - 识别教程中的示范区间、参数说明和前后对比。

3. **原子化技巧卡**
   - 把教程拆成字幕、动效、声音等独立技巧。
   - 每张技巧卡至少包含：
     - 解决的表达问题；
     - 源视频和时间码；
     - 参数、持续时间和同步关系；
     - 适用与禁用场景；
     - 所需素材和依赖；
     - 短预览；
     - 当前置信度；
     - 原创重建与版权边界。

4. **按职责路由**
   - 字幕、动效和声音技巧分别进入对应 Agent 的待审核记忆。
   - 跨领域玩法通过共享 `Combo Recipe` 关联，例如“关键词放大 + 回弹 + Whoosh/Click”，而不是在三个库里复制同一份内容。

5. **沙盒重建**
   - Agent 必须在本地测试口播上重新实现技巧。
   - 通过可读性、遮挡、时间同步、响度和完整解码 QA 后，才认为“能够复现”。

6. **分级晋升**

```text
Inbox（机器提取）
→ Candidate（专家完成结构化理解）
→ Recreated（测试片重建成功）
→ Validated（真实视频中由用户批准）
→ Preferred（跨视频多次胜出）
→ Brand Core Candidate（可提议进入品牌骨架）
```

任何阶段都允许降级、过期或进入负面记忆。

## 五、流程 B：视频生产

1. 总控冻结内容、原片、技术参数和本次允许使用的记忆版本。
2. 程序生成内容时间轴、逐秒帧、镜头变化和音频事件。
3. 专家 Agent 在隔离上下文下并行检索经验并提出候选。
4. 冲突检查器提前识别遮脸、字幕过载、声音抢人声、节奏碰撞和素材授权问题。
5. 总导演整理出少量差异明确的关键帧候选。
6. 用户审核关键帧；被否决方案保留原因，不直接删除。
7. 胜出方向生成多个 15～25 秒动效与声音样片。
8. 留存质检和独立批评 Agent 按时间码盲评。
9. 用户选择、组合或返修；只将胜出方案扩展为完整视频。
10. 完整成片执行技术 QA 和最终人工审核，不自动发布。

前期内部候选数量不以计算成本为约束，但面向用户的候选必须经过差异性筛选，避免审核疲劳。

## 六、闭环 C：评测、记忆治理与品牌发现

### 发布前信号

- 用户选择了哪个候选；
- 被拒绝或被组合的原因；
- 具体时间码返修；
- 逐秒观看理由审计；
- 字幕、动效、声音和构图的独立评分；
- 完整视频是否通过最终人工审核。

### 发布后信号

- 关键时间点留存；
- 完播率；
- 重复播放；
- 点赞、收藏、评论和分享；
- 与内容主题和流量来源相关的上下文。

平台数据不能直接覆盖人工判断。系统必须记录选题、开场、发布时间和分发量等干扰变量；证据不足时只提高或降低假设置信度，不宣布因果关系。

### 品牌发现期

- 前 10～20 条视频视为受控实验，而不是提前锁定视觉模板。
- 内容品牌骨架先保持稳定：
  - 从知道到做到；
  - 普通人的 AI 行动实验；
  - 结果先行和真实证据；
  - 真人口播；
  - 不虚构成果；
  - 给观众可执行的小任务。
- 视觉和声音变量允许探索，但每次实验必须记录改变了什么。
- 跨视频重复胜出、获得人工批准并得到发布数据支持的元素，才成为品牌骨架候选。

## 七、本地记忆模型

### 1. 共享证据库

保存原视频、转录、时间码、抽帧、音频事件、来源和授权信息。它是事实层，不保存审美结论。

### 2. Agent 私有记忆

每个专家只保存与职责相关的案例、参数、适用条件、失败边界和评测结果。私有记忆不能直接修改其他 Agent 的判断标准。

### 3. 共享创作资产库

保存可预览、可调用的字幕、动效、音效、配音位置和组合配方，以及实现依赖和版本。

### 4. 品牌假设库

每条假设包含支持证据、反例、置信度、适用内容、首次出现时间、最近验证时间和当前状态。

### 5. 负面记忆

保存被拒绝方案、失败组合、质量问题、使用条件和返修原因。负面记忆用于避免重复踩坑，不用于永久封禁可在其他场景有效的技巧。

### 6. 记忆晋升规则

- 自动提取只能进入 Inbox。
- Agent 总结只能进入 Candidate。
- 沙盒真实重建成功后进入 Recreated。
- 用户批准后进入 Validated。
- 跨视频重复胜出后进入 Preferred。
- 进入品牌骨架必须由用户明确确认。
- 所有记忆必须可版本化、可回滚、可降级、可过期。

第一阶段的“训练”指外部记忆检索、经验评分和提示词/规则版本迭代，不进行基础模型微调。是否需要微调只能在积累足够标注样本并证明检索式记忆达到瓶颈后重新评估。

## 八、主要风险与缓解措施

| 风险 | 缓解措施 |
| --- | --- |
| 会总结但不能复现 | 必须经过沙盒重建和真实渲染 QA |
| 好元素组合后互相打架 | 组合前执行遮挡、密度、响度和时序冲突检查 |
| 单条视频表现无法归因 | 控制实验变量，记录选题和流量上下文，只维护置信度 |
| 同一模型造成伪多 Agent | 隔离上下文、不同评分标准、盲评、允许明确反对 |
| 记忆污染或陈旧 | 来源、版本、置信度、有效期、降级和回滚 |
| 探索破坏品牌一致性 | 固定内容价值和人物身份，只开放部分视觉/声音变量 |
| 用户审核疲劳 | 内部多探索，外部只展示差异最大的少量候选 |
| 版权和授权混淆 | 学习原理并原创重建；素材使用单独记录授权 |
| Agent 讨论不可复现 | 所有输入、输出、记忆版本和决策理由落盘 |
| 系统复杂度超过收益 | 分阶段上线，并与当前 v4 基线进行对照 |
| 重复造轮子或引入不成熟依赖 | 先执行开源复用门禁；对候选做许可证、安全、维护、兼容性和退出成本评估 |

## 九、分阶段验证路线

### 阶段 0：基线冻结

- 冻结当前 `visual-director-v4` 的样本任务、提示词、输出和 QA。
- 建立同一素材、同一内容、同一技术参数的对照基线。
- 对 Agent 编排、长期记忆、视频理解、字幕/动效/声音资产和评测框架执行 GitHub/官方生态候选调研，形成复用决策记录。

### 阶段 1：知识摄取 MVP

- 支持一个教学视频生成来源包、技巧卡和组合配方。
- 至少完成字幕、动效、声音三类技巧的沙盒重建。
- 不接入现有生产默认路径。

### 阶段 2：影子模式多 Agent

- 专家 Agent 针对真实任务生成候选，但不影响当前 v4 成片。
- 比较候选差异度、质检覆盖率和用户偏好。

### 阶段 3：关键帧与样片接管

- 多 Agent 只接管关键帧和 15～25 秒样片提案。
- 当前总控、渲染、QA 和人工审核门保持不变。

### 阶段 4：完整生产与品牌发现

- 胜出方案扩展到全片。
- 连续 10～20 条视频积累发布前和发布后证据。
- 形成第一版经用户确认的品牌骨架。

## 十、未来实施验收标准

- 同一教程可拆成多类技巧卡，且每张均可追溯到具体时间码。
- 原视频只保存一份，Agent 私有记忆不复制大文件。
- 至少三个专家 Agent 能在隔离上下文下产生可辨识的不同候选。
- 独立批评 Agent 的评语必须引用具体时间码和评价标准。
- 每次生成可追溯使用的模型、提示词、记忆、资产和规则版本。
- 技巧必须经过沙盒重建和 QA，才能进入可推荐状态。
- 用户可以批准、拒绝、降级、过期或回滚任何长期记忆。
- 关键帧、短样片和完整成片的现有人工审核门不被削弱。
- 逐秒审片解释观看理由，不把“每秒有新特效”设为硬指标。
- 发布数据只用于校准置信度，不在缺少对照时宣称因果。
- 当前 v4 可作为稳定基线和回退路径。
- 系统在品牌发现期结束后能输出带证据、反例和置信度的品牌骨架候选。
- 每个新增 Agent、Skill、工作流或基础组件都有开源候选清单、许可证/安全/维护/兼容性评估和复用或自建理由。
- 第三方组件必须固定版本、通过隔离环境验收，并具有退出或回退方案。

## 十一、非目标

- 第一阶段不训练或微调基础模型。
- 不允许 Agent 自主发布视频。
- 不允许 Agent 未经验证自行修改品牌骨架。
- 不把所有机械分析包装成 Agent；抽帧、ASR、镜头检测和技术 QA 继续使用程序。
- 不要求每秒新增视觉或声音刺激。
- 不复制未授权的原作者素材、字体、音效或工程文件。
- 不一次性替换现有 v4 全链路。
- 不在未完成 GitHub 与官方生态能力发现前从零创建 Agent、Skill、工作流或通用基础组件。
- 不因为项目开源就未经审计、固定版本和本地验收直接接入生产。

## 十二、下一步权限门

本设计获书面复核后，下一步只能创建实施计划。实施计划需要明确：

- 第一阶段范围和文件边界；
- GitHub 与官方生态候选调研、评估矩阵和复用决策；
- 本地记忆的具体存储格式与索引方式；
- Agent 调用协议和结构化输入输出；
- 测试、回滚和对照实验；
- 与现有 `visual-director-v4` 的渐进集成点；
- 每一阶段的停止条件。

在用户批准实施计划前，不开始代码修改。
