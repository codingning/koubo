# Koubo 多 Agent 知识训练与候选研究规格

日期：2026-07-24  
状态：Ready / 第一阶段候选发现执行中

## 任务理解

- 目标：为 Koubo 的内容、字幕/动效、声音和导演剪辑能力建立可追溯、可复刻、可回滚的本地知识基础，再用真实口播片段验证跨 Agent 协作效果。
- 用途：支持用户持续制作“从知道到做到”的 AI 实践型口播视频，同时减少空泛脚本、固定模板和未经验证的剪辑经验。
- 第一阶段交付物：四条知识线的抖音候选教学视频清单，供用户批量确认。
- 完成标准：每条知识线形成约 3 条作用互补、完成沙盒复刻的技巧，并至少有 1 条技巧在真实口播片段中通过用户审核，随后才进入小规模组合测试。

## 已确认决策

1. 同步建设四条知识线：
   - 内容策略与普通观众评审；
   - 字幕与动效；
   - 声音设计；
   - Director 导演剪辑。
2. 知识发现和沙盒复刻可以并行；真实视频生产必须遵守依赖顺序：

   ```text
   用户方向
   → Content Strategist 访谈与分析
   → 用户确认方向
   → Script Agent 成稿
   → Ordinary Viewer Critic 稿件评审
   → Caption / Motion / Sound 并行提案
   → Director 选择和组合
   → 渲染
   → 成片 Critic、技术 QA 与用户审核
   ```
3. HyperFrames 和 Remotion 都是可选执行引擎，不预设默认和对照身份。
4. Director 必须根据当前任务选择引擎，并留下可审计理由；允许同一视频的不同片段使用不同引擎后再合成。
5. 采用两级批量审核：
   - 第一级：用户先确认候选教学视频；
   - 第二级：复刻与评测完成后，用户批量确认哪些技巧晋升为正式知识。
6. 不要求用户逐张审批机器提取的技巧卡；未晋升内容始终停留在候选层。

## 本地知识存储

`F:\code\koubo` 是运行事实的权威来源：

- `docs/research/`：研究报告、来源说明、观点与方法蒸馏；
- `config/multi-agent/`：可审阅、可版本化的候选原则和角色知识；
- `data/multi-agent/`：运行 artifact、SQLite 状态、晋升事件和回滚事实；
- 本地媒体资产：只保存合法取得且任务需要的证据、沙盒复刻和评测产物。

Obsidian Vault 只保存长期决策、工作流、项目状态和关键结论，不作为原视频、完整转录或运行数据库的替代品。

知识状态沿用：

```text
Inbox
→ Candidate
→ Recreated
→ Validated
→ Preferred
```

自动提取最多进入 `Candidate`；没有原创复刻和真实评测证据，不得进入长期推荐库。

## 来源与版权边界

- 抖音教学视频用于发现创作原则、案例和待验证方法。
- Remotion、HyperFrames、FFmpeg、音频技术和工程实现以官方文档、官方仓库、可运行示例和固定版本行为为主要事实源。
- 不复制原作者的原句、案例、人设、画面、代码、模板、素材包或授权不明资产。
- 每条技巧必须记录来源、时间码、适用条件、禁用条件、版权边界、复刻结果和失败记录。
- 候选视频未经用户确认，不完整下载、转录或进入长期知识库。

## 引擎选择合同

Director 按以下证据选择 HyperFrames、Remotion、FFmpeg 或组合路径：

- 语义动效和时间线需求；
- 字幕、媒体、音频与交互的同步精度；
- 现有可复用组件与实现复杂度；
- 确定性渲染、可寻址性和回归测试能力；
- 输出画幅、性能和兼容性；
- 当前固定版本上的真实渲染结果；
- 失败后的降级、替换和回滚成本。

不得因为历史默认、Agent 偏好或示例数量直接选定引擎。出现实质分叉时，先做最小同素材样片，再由证据决定。

## 第一阶段执行边界

本阶段只允许：

- 只读搜索公开视频；
- 保存候选链接、作者、标题、公开互动信息、命中知识线和发现层风险；
- 去重并形成少量可审核候选。

本阶段不允许：

- 未经用户确认就批量下载或完整转录；
- 把搜索摘要当作已看完视频；
- 自动晋升知识；
- 自动修改生产默认、批准成片或发布视频；
- 仅凭点赞、标题或作者自述认定教学有效。

## 候选确认后的验证门

每项待晋升技巧必须满足：

1. 来源、时间码、适用条件和版权边界明确；
2. 在本地用原创代码或合法资产完成一次沙盒复刻；
3. 技术 QA 通过，并记录失败与回滚参数；
4. 至少在一个真实口播片段中接受用户审核；
5. 与同组其他技巧作用互补，而不是同一种模板的重复变体。

每组达到约 3 条上述技巧后，进行一次小规模组合测试。数量只是起步参考，证据质量优先；没有通过真实审核时，不因数量达标而自动进入组合测试。
