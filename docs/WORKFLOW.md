# AI成长优先的每日内容工作流

## 0. 基本原则

内容先来自真实实践，热点后置，**热点只做辅助，不再承担账号主线**。每日顺序必须是：

> 真实Codex任务与产物 → 证据和失败 → 候选选题 → 相关热点辅助 → 素材包 → 人工审核 → 数据与学习复盘

当天没有足够真实素材时，可以只记录进展，不强行生成主选题。

## AI选题与同题视频研究门禁

1. 先从真实个人进度中选择一个明确的 AI 工具、方法、项目、工作流、学习或能力边界问题；个人进度只能作为证据。
2. 生成 2—3 个抖音同题搜索词，读取用户指定参考账号的近期视频并补充同题搜索。
3. 至少一条相关视频必须完成完整内容核验；默认在本机下载临时副本并用 faster-whisper 转录，分析后删除原视频和全文转录。
4. 研究包分别记录：视频结构、分享的知识、评论/收藏机制、讨论信号、适用边界和禁止复制项。
5. 标题、简介、指标和评论属于 metadata-only，只能发现方向；未读完整视频时不得声称已经拆解其知识和结构。
6. 研究门禁通过后才生成口播；完整版固定 2—3 分钟、550—950 个有效字符、7—12 段，衍生短版不作为默认拍摄稿。
7. 成稿必须记录实际使用的来源 ID，并说明如何用本人的真实证据形成原创变化。

## 1. 读取当天真实记录（10分钟）

先查看：

1. 当天真实完成的Codex任务和项目目标；
2. 新建、修改或交付的文件与功能；
3. 实际运行的命令、测试和验收结果；
4. 错误、失败、返工和被放弃的方案；
5. 可公开的截图、终端输出和前后对比；
6. 昨天留下的挑战及今天的验证结果；
7. 真实收到的粉丝问题；没有则明确留空。

填写 `growth/00_daily_progress.md`。只记录证据能够支持的事实。

## 2. 敏感信息预检（5分钟）

在任何内容加工前先排除：

- API Key、令牌、Cookie、密码、私钥和内部地址；
- 私人聊天、客户资料、未授权仓库和个人文件；
- 不能公开的公司信息、付费内容和第三方素材；
- 可识别个人身份的路径、账号和通知内容。

证据不可公开时，只能做脱敏重制；无法安全重制的内容不能做主选题。

## 3. 建立证据卡（5分钟）

每个可能的故事至少写清：

- 真实动作；
- 预期结果；
- 实际结果；
- 冲突或变化；
- 证据文件/截图；
- 观众收益；
- 与30天路线的关系；
- 明日挑战。

没有结果、冲突或证据的学习笔记不进入主选池。

## 4. 最多5个候选方向（10分钟）

固定方向：

1. 今日进度型；
2. 今日踩坑型；
3. 成果展示型；
4. AI热点亲测型；
5. 成长反思或真实粉丝共创型。

某类没有真实素材时写“空缺：无真实证据”，不得为了凑满5个虚构。

## 5. 热点辅助（可选，10—20分钟）

只采集与当天学习路线、工具或项目直接相关的AI热点，用于：

- 判断观众是否正在关心同一问题；
- 给真实进展寻找更容易理解的切口；
- 选择一个功能亲手验证；
- 辅助标题、封面和结尾问题。

保留原有抖音、小红书、微博、AI官方、国际新闻和RSS降级矩阵。热榜只能证明有人讨论，不能替代本人的真实实验和事实源。

## 6. 评分与主选门槛（10分钟）

按 `config/scoring.json` 的九个正向维度和一个风险维度评分。

```text
正向加权分 = Σ（九个正向维度 × 权重）÷ 10
风险扣分 = max(0, 风险-3) × 3
推荐指数 = 正向加权分 - 风险扣分
```

主选题必须同时满足：

- 真实性和证据充分度≥8；
- 至少一个可公开展示结果；
- 明确的一句话观众收益；
- 有一个具体的观众代入场景；
- 有一个低门槛、可回答、与下一集相关的评论问题；
- 有明确的持续关注理由，说明下一集会验证或展示什么；
- 不只是“今天学了什么”；
- 隐私、版权和表达风险≤5；
- 有明日挑战或下一集悬念。

不满足时不选主选题。

## 7. 成长型素材包（15—25分钟）

使用 `templates/daily_content_package.md`，完成16项交付。

先写清本集只解决的一个问题，再选择口播结构：

- **证据故事 `evidence-story`**：有真实失败、干预和结果时使用。按“精准矛盾 → 观众代价 → 个人证据 → 关键动作和结果 → 2—4项方法 → 边界 → 最小行动”推进；
- **可收藏路径图 `saveable-map`**：观众缺少先后顺序或阶段判断时使用。给3—5个阶段，每阶段必须有问题、动作和完成信号；
- **短共鸣 `short-resonance`**：只用于从完整版派生60—90秒短版，不再作为默认完整口播结构。

个人经历是证据，观众问题才是叙事主线。方法段必须能执行，并明确做完后看什么信号。只复用外部样本的结构逻辑，不复刻措辞、案例、标题或人设。

语气保持轻松、口语化和可亲近：2—3分钟完整版放2—3个自然轻松点，最多使用一个与冲突高度相关、来源已核对的近期热梗；不连续玩梗，不让热梗替代事实。禁止使用“你怎么看”“欢迎留言”“记得点赞关注”等空泛互动口号。

评论问题、观众最小任务和下一条验证都要在策划中写清，但口播结尾从中选择一个主动作，合并成一句自然收束；不连续念三句运营口号。

证据故事和可收藏路径图的完整版统一控制在120—180秒、550—950个有效字符、7—12段。短共鸣仅用于60—90秒衍生短版，必须比完整版更短且信息闭环。

## 8. 人工审核门（10分钟）

逐项确认：

- 所有进展、失败、数字和反馈均有真实记录；
- 证据已经脱敏且允许公开；
- 没有把AI生成内容说成本人亲历；
- 没有把计划写成已完成；
- 没有虚构粉丝问题；
- 标题和封面没有夸大结果；
- 第三方图片、音乐、视频和代码具备使用权限；
- 不包含医疗、金融、法律等未经审核的高风险建议。

本项目不自动发布或评论。

## 9. 发布后回填

在 `data/content_ledger.xlsx` 回填：

- 成长天数、栏目、AI项目/学习路线；
- 真实进展、证据、踩坑、观众收益和明日挑战；
- 标题、封面、时长和开头；
- 播放、留存、完播、互动和涨粉；
- 学习结论和内容结论。

建议发布后2小时、24小时、72小时更新数据。

## 10. 每周双重复盘

### 个人学习复盘

- 本周真正完成了什么；
- 哪些能力可以独立完成；
- AI在哪些地方有效或不可靠；
- 哪些错误重复出现；
- 下周项目挑战是什么。

### 账号内容复盘

- 哪类真实变化最容易让人停留；
- 哪类证据画面最有效；
- 哪种钩子、标题、封面和口语表达最好；
- 哪些内容像流水账或念稿；
- 下周增加、减少、停止什么。

至少观察同类3条，不因单条数据改变方向。


## 11. 同步到网页工作台

每天素材包通过结构校验后，由Codex把当前可拍内容同步到 `web/data/content-data.js`。用户只需双击 `打开口播工作台.html` 或刷新已经打开的页面，即可查看新稿、使用提词器和完成审核，不需要手动运行脚本。

网页只提供本地查看、复制、选择和审核记录，不自动发布、不上传文件，也不覆盖Markdown和Excel源数据。
