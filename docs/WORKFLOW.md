# Codex / Agent / Skill 实测内容工作流

## 0. 基本原则

不设置30天、Day编号、日更承诺或固定每日任务。内容由真实证据和可交付资产触发：

> 明确开发者问题 → 真实安装/运行/失败/修复 → 形成可复用资产 → 选择选题 → 生成拍摄包 → 人工审核 → 发布数据与资源领取复盘

没有真实运行结果或可交付资产时，不生成口播。

## 1. 建立问题与受众合同

每次只锁定：

- 哪类 Codex / Agent / Skill 用户；
- 一个具体场景和一个核心问题；
- 观众看完能完成的动作或判断；
- 视频内交付什么，社群中补充什么；
- 哪些事实仍未验证。

Content Strategist 可以追问和指出证据缺口，但不能换题或自动安排下一条。

## 2. 证据预检

至少包含一种E1直接证据：

- 固定版本和官方来源；
- 真实安装或运行输出；
- 输入与输出文件；
- 失败日志与修复差异；
- 测试、截图、流程图或前后对比。

开源项目还必须检查源码与官方产品关系、许可证、安全、维护状态、Windows兼容性、隐私和退出成本。

## 3. 形成资源资产

在写稿前先冻结本条视频的资源对象：

- 提示词；
- 工作流图；
- 检查清单；
- 模板；
- 安装或验证步骤。

资源必须有名称、版本、适用范围、文件清单和已验证状态。视频内给完整核心方法，群内提供文件化版本、更新和答疑。

## 4. 从开放选题池选择

不固定数量和比例：

- Skill真实跑通；
- Agent工作流拆解；
- 开源项目审计。

主选题必须同时满足：有直接证据、结果可视化、开发者收益明确、存在可交付资产、风险边界可说明。项目进度、泛成长感悟和纯资讯不能成为主选。

## 5. 外部研究

研究官方文档、官方仓库和可信生态；需要参考公开视频时，至少完整核验一条来源。标题、简介、播放指标和评论只能用于发现问题，不能冒充完整内容。

只复用知识结构和验证方法，不复制原句、案例、人设、素材或未授权代码。

## 6. 自适应拍摄包

根据题材选择：

- `quick-proof`：25—45秒，一个结果和一个资产；
- `evidence-story`：45—90秒，失败、修复和验证；
- `saveable-map`：45—110秒，3—5步工作流；
- `deep-audit`：60—150秒，来源、许可、安全、安装和结论。

统一顺序是：

1. 0—5秒展示结果、失败或交付物；
2. 说明谁会遇到这个问题；
3. 展示最小复现步骤；
4. 用真实输出验证；
5. 说明边界；
6. 只保留一个自然收束。

代码、命令、配置和安装过程在帮助目标用户复现时可以进入正文，但必须与画面和结果一一对应。

## 7. 人工审核

- 所有版本、结果、数字和错误都有证据；
- 没有把 README、自述或计划当作实测；
- 每个步骤都有真实完成信号；
- 视频内没有故意扣留核心步骤；
- 群资源确实存在且与视频承诺一致；
- 标题封面没有夸大“一键”“全自动”“适用所有项目”；
- 隐私、版权、许可证和平台导流边界已检查。

本项目不自动发布、不自动评论、不自动建群或发送资源。

## 8. 发布后复盘

不按天数复盘。每完成一组可比较内容后，查看：

- 2秒跳出、5秒完播、平均观看与完播；
- 点赞、评论、收藏、主页访问和涨粉；
- 抖音群/微信群的真实资源领取；
- 哪种结果画面、资产类型和选题池带来有效转化；
- 哪些内容仍像工具介绍或项目汇报。

历史最佳基线用于比较，但不提前承诺固定发布数量。

## 9. 网页工作台

生成内容自动进入 `web/data/content-data.js` 与本地内容列表。历史成长内容和旧热点内容只保留在“历史内容”，不再驱动新选题、评分、时长和生成规则。
